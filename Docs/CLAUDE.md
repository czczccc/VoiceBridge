# Claude Code 项目指令

## 工作方式

1. 开始前阅读根目录 `README.md`，以及 `Docs/` 下的 `README.md`、`PRD.md`、`ARCHITECTURE.md`、`PROTOCOL.md`、`SECURITY.md` 与 `TASKS.md`。本文及任务文档均保留在 `Docs/`。
2. **`TASKS.md` 是唯一任务顺序来源。** 一次只实现当前一个 TASK，不擅自跳到后续任务。
3. 先检查当前仓库状态、工具链和现有代码；不要覆盖用户已有实现。
4. 每次改动范围保持小，优先添加测试，再实现功能。
5. 按用户约定：本地编码及格式、配置等不需要编译的检查；编译、打包及依赖编译的检查和自动化测试统一在 GitHub Actions 执行；用户下载产物后进行手机真机与 Windows 手工测试。每个 TASK 记录 CI 和真机的实际结果；没有结果时标记待验证，不在本机启动编译。
6. 更新 `TASKS.md` 中的状态、验收结果和剩余风险。
7. 最终报告必须区分“已验证”“未验证”“假设”，不得声称未运行的测试通过。

## 产品约束

- 语音识别由用户当前 Android 输入法完成；不要添加自建 ASR、`SpeechRecognizer` 或录音流水线。
- 不自动点击第三方输入法麦克风，不使用 Accessibility 绕过 Android 限制。
- Android 通知操作只能通过用户点击打开 Activity；不能假设后台能强制弹出键盘。
- 实时同步发送带 `sessionId` 和递增 `seq` 的完整文本快照。
- Windows 注入必须有用户明确启动的 session、焦点检查、停止机制与超时处理。
- 禁止每次快照都使用 `Ctrl+A` 后粘贴全文。
- 焦点改变时暂停，不自动向新窗口注入。
- 不要宣称支持所有 Windows 控件；兼容性必须基于测试。
- 正式局域网连接必须认证并验证服务器证书指纹；不能把无认证明文 WebSocket 作为正式实现。
- 不记录输入正文、剪切板正文、认证令牌或私钥。
- 不实现 iOS、云中继、图片/文件同步，除非用户明确要求修改范围。

## 代码质量

- 网络协议、状态机、文本差异算法与 Windows 注入后端分层。
- 不将系统 API 逻辑塞进 React 组件。
- Kotlin 与 Rust 代码必须处理错误，不允许用空 `catch` 隐藏异常。
- 异步任务必须可取消；停止 session 时清理待处理消息。
- 处理 Unicode 时避免拆分 UTF-16 代理对；明确记录偏移单位（UTF-16 code unit 或 Unicode scalar）。
- 所有外部消息都要验证版本、长度、序号与会话状态。
- 新增协议字段时同步更新 `PROTOCOL.md` 和测试样例。

## 首次启动

执行 TASK-000。先报告当前环境、将创建的目录和需要的依赖；确认没有覆盖已有文件后再创建。两端最小项目的实际构建由 GitHub Actions 验证，手机真机测试由用户完成；结果尚未取得时不得勾选任务完成。
