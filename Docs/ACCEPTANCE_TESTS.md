# MVP 验收测试

验证分工：代码在本地开发；编译、打包与自动化测试在 GitHub Actions 执行；Android 手机真机与 Windows 手工测试由用户使用 CI 产物完成。未收到实际测试结果时保持未勾选。TASK-000 的首轮真机检查仅确认安装和欢迎页启动，不代表下列业务功能已实现。

## A. Android 输入法与文本状态

- [ ] 打开 App 后，文本框可获得焦点；系统允许时自动弹出当前默认输入法。
- [ ] 不要求用户切换输入法；当前 IME 可正常输入中文和英文。
- [ ] 使用微信输入法进行语音输入，识别文字能进入 App 文本框。
- [ ] 使用百度/搜狗/豆包输入法逐一测试（仅对实际测试的版本宣称兼容）。
- [ ] 普通键盘输入、删除、选中替换、粘贴、清空都能更新本地文本状态。
- [ ] 记录输入法是否提供中间结果；不能把“输入法未输出中间结果”误判为网络延迟。
- [x] 通知栏点击操作会打开输入页；系统拒绝弹键盘时可手动点击文本框。（2026-10-27 用户确认通知入口与键盘正常；键盘被拒场景未单独记录）
- [ ] 通知权限被拒绝时，输入、配对与同步仍可正常使用；通知栏入口不可用，并给出说明。
- [ ] 打开 App 直接进入语音页，微信输入法麦克风可用；语音识别文字能进入当前段输入框。
- [ ] 键盘被收起时页面提示「点一下输入框继续说话」；点击输入框后键盘恢复，仍可继续说话。
- [ ] 配对、通知入口和版本更新位于「设置」页；返回语音页后与电脑的连接不中断。
- [ ] App 不自行录音、不请求 ASR 权限、不自动点击第三方 IME 麦克风。

## B. 网络与配对

- [ ] 未配对设备不能建立已认证会话。
- [x] Windows 本地服务可在界面启动/停止，并显示监听地址与端口；局域网访问在配对完成前不可开启。（2026-10-27 用户截图确认：显示“运行中”与 127.0.0.1:47615，局域网按钮不可用；停止按钮行为未单独截图确认）
- [ ] 未认证客户端发来的任何消息都被拒绝，且日志不出现正文。
- [ ] 错误证书指纹、过期配对码、错误凭据均被拒绝。
- [ ] Wi-Fi 断开后 UI 显示断线；重新连接后可恢复普通连接。
- [ ] 网络重连不会自动恢复旧输入 session。
- [ ] 重复消息与旧 seq 被丢弃。
- [ ] 超过消息大小上限的 payload 被拒绝。
- [ ] Windows 服务退出后不再监听端口。

## C. 实时文本输入

- [ ] 在电脑上点选目标输入框后，手机开始输入即自动同步（无需在电脑上点开始）。
- [ ] Android 文本从空字符串变为“你好”，Windows 只出现一次“你好”。
- [ ] 连续更新“你”→“你好”→“你好世界”，Windows 最终只保留“你好世界”，不出现“你你好你好世界”。
- [ ] 尾部删除与标点修正能正确反映到 Windows。
- [ ] 输入法将整句改写时，Windows 能在支持的目标控件中替换旧尾部。
- [ ] emoji、中文、英文、数字、换行测试不产生乱码。
- [ ] 输入会话期间将焦点切换到另一个窗口，应用立即暂停注入。
- [ ] 焦点变化后发送的旧快照不会进入新窗口。
- [ ] 停止会话后，迟到的消息被拒绝。
- [ ] 一段文字发送后，手机输入框自动清空；下一段追加在电脑上，不重复、不删除上一段。
- [ ] 段内退格能修改电脑上的文字；跨段后回改只影响新段。
- [x] 远程文本中的换行不会在电脑端产生 Enter 或发送消息；只有用户在本机按 Enter 才发送。（2026-10-27 用户真机确认长段落中途停顿不再自动回车）
- [ ] 点「新一段」立即结束本段。
- [ ] 目标控件不兼容时显示错误，不无限重试、不造成重复输入。
- [ ] 不存在 `Ctrl+A` 选择整个文档后粘贴的实现。

## D. 剪切板

- [ ] Android 前台主动发送纯文本到 Windows。
- [ ] Windows 复制纯文本后，在 Android 允许的场景中同步或显示“点按复制”。
- [ ] 同步消息不会无限循环。
- [ ] 用户再次主动复制相同文本时仍允许发送。
- [ ] 两个方向可独立关闭。
- [ ] 关闭剪切板同步后不继续传输。
- [ ] 图片与文件未被误认为已支持。

## E. 安全与隐私

- [ ] 日志不包含测试文本正文、剪切板正文、pairing token 或私钥。
- [ ] 未配对客户端不能触发输入注入。
- [ ] 焦点变化会暂停输入。
- [ ] 撤销设备后，该设备不能重新连接，除非重新配对。
- [ ] 不默认开放公网监听，不创建公网端口映射。
- [ ] 退出 Windows App 后输入会话与服务停止。
- [ ] Android 端可查看和移除配对电脑。

## F. 性能目标

测试设备和网络条件必须记录，不能把目标当作已验证事实。

- [ ] 在稳定局域网、普通文本框中，测量 Android 文本状态变化至 Windows 开始应用的延迟。
- [ ] P95 目标 ≤ 150 ms（不含输入法语音识别自身耗时）。
- [ ] 连续编辑 100 次后无重复注入。
- [ ] 连续断连/重连 20 次后无旧 session 内容被注入。
- [ ] 长文本达到配置上限时有明确错误提示。

## G. 发布阻断项

下列任意一项未通过，不应将构建标记为稳定版：
- 未认证设备可以发起文本注入。
- 焦点切换后仍持续向新窗口注入。
- 文本快照造成重复输入且无可靠恢复方式。
- 认证凭据或输入正文进入日志。
- 正式 LAN 模式仍使用未经认证的明文 WebSocket。

## H. 测试版应用内更新

- [x] Android：应用内检出更高版本并覆盖安装，数据保留。（2026-10-27 从 0.1.0-test.2 升至 0.1.0-test.4）
- [ ] Android：签名或摘要不匹配的 APK 不予安装。
- [ ] Windows：应用内检出更高版本、下载后自动安装并重启，设置保留。
- [ ] Windows：更新包签名不匹配时拒绝安装。
- [ ] 两端在断网或发布渠道不可达时给出失败提示，现有功能仍可用。
