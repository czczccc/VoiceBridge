# PRD：LAN Voice Bridge

- 文档版本：0.1
- 状态：MVP 方案
- 平台：Android + Windows 11（优先）；暂不支持 iOS
- 客户端技术：Android Kotlin + Jetpack Compose；Windows Tauri 2 + Rust + React/TypeScript
- 通信：局域网 WebSocket
- 产品定位：个人可用、后续可开源或产品化的跨设备协同输入工具

## 1. 产品概述

### 1.1 一句话描述

用户在 Android App 的文本框中使用自己熟悉的输入法进行语音输入，识别出的文字通过局域网实时同步到 Windows 当前输入位置；同时支持手机与电脑之间的纯文本剪切板同步。

### 1.2 核心原则

1. **复用输入法**：微信输入法、百度输入法、搜狗输入法、豆包输入法及其他遵循 Android IME 机制的输入法均可尝试兼容；产品不集成自己的 ASR。
2. **实时同步文本状态**：监听文本框变化，发送带序号的完整快照；不能假设输入法每次只增加一个字。
3. **用户控制电脑输入**：Windows 输入会话需由用户明确启动；焦点变化时暂停注入。
4. **局域网优先**：MVP 不需要云账户、云中转或公网服务。
5. **安全默认**：配对后才接受消息；不将文本写入长期日志；用户可随时停止输入会话。
6. **分阶段实现**：先跑通纯文本语音输入链路，再做双向剪切板和扩展功能。

## 2. 用户与场景

### 2.1 目标用户

- 经常在 Windows 上使用聊天工具、浏览器、IDE、文档软件的人。
- 更习惯手机输入法语音识别的人。
- 希望不安装 Windows 麦克风驱动、不购买独立麦克风，也能快速向电脑输入中文的人。
- 需要手机与电脑之间局域网文本同步的人。

### 2.2 主要场景

- 在电脑的 ChatGPT、网页表单、即时通讯软件、文本编辑器中输入较长中文。
- 用户打开手机 App，使用手机输入法的麦克风完成语音转写。
- 识别过程中的文本更新实时反映到 Windows。
- 手机复制一段文字，发送到电脑剪切板；电脑复制文字后同步到手机（受 Android 剪切板权限与前台限制约束）。

## 3. 关键用户流程

### 3.1 首次配对

1. 用户在 Windows 打开应用，保持局域网服务运行并广播配对服务。
2. Android 打开 App，自动发现同一局域网内的电脑，列表显示电脑名称。
3. 用户点选目标电脑，Android 显示 6 位配对码；Windows 同时弹出请求并显示同一配对码。
4. 用户在两端核对配对码一致后确认；不一致则拒绝。
5. 双方交换长期设备凭据，连接成功，显示设备名、局域网连接状态和最近连接时间。
6. Windows 只在用户授权的网络接口/防火墙范围内监听。

发现广播只用于定位候选设备，不能作为信任依据；无法接收 mDNS 的网络（如 AP 隔离）允许手动输入 Windows 地址。

### 3.2 语音输入

1. 用户在 Windows 端点击“开始输入会话”，或通过可配置的全局快捷键启动。
2. Windows 端记录当前目标窗口/控件的焦点标识（可获得时）、会话 ID、起始文本状态。
3. 用户打开 Android App；文本框获得焦点并请求显示系统输入法。
4. 用户点击输入法自己的语音按钮，进行语音识别。
5. Android 监听文本框变化；输入法每次更新文本时，发送 `text.snapshot`。
6. Windows 校验设备、会话 ID、序号与目标焦点；对比新旧快照并注入文本差异。
7. 如果焦点改变、会话被停止或目标窗口不可用，暂停注入并提示用户；不把后续文本发到未经确认的新窗口。
8. 用户结束输入会话，手机端文本保留在当前页面，用户可复制或重新发送。

**说明：** “每字同步”指输入框每次实际变化都尽快同步。部分输入法会先显示临时文本、后整段修正，或只在语音识别结束后提交；产品不能强制输入法提供逐字结果。

### 3.3 剪切板同步

- Windows → Android：Windows 监听文本剪切板变更，通过 WebSocket 发送 `clipboard.text`。Android 仅在 App 前台或用户触发的明确场景中更新系统剪切板，避免后台静默读取/写入引发隐私与系统限制。
- Android → Windows：Android 在前台读取用户主动复制的文本或点击“发送剪切板”后发送。
- 两端携带 `originDeviceId`、`eventId` 与时间戳，避免重复同步循环。
- MVP 只支持纯文本；图片和文件列入后续版本。

## 4. 功能需求

### P0：MVP 必须完成

**F-001 设备配对**
- 通过 mDNS 自动发现同一局域网内的电脑，无需手动输入 IP；无法发现时允许手动输入地址。
- 配对需两端显示同一 6 位数字码，由用户核对一致后在两端确认。
- 未配对设备不能发送文本或剪切板内容。
- 支持移除设备、重新配对。

**F-002 连接状态**
- 展示已连接、连接中、断开、认证失败状态。
- 断线自动重连，采用指数退避并设置上限。
- 网络切换后重新发现或允许手动输入电脑 IP。

**F-003 输入法文本框**
- Android 主界面有一个明确的多行文本框。
- 点击页面或打开 App 后将焦点交给文本框，并在系统允许时弹出当前默认 IME。
- 不指定、不替换用户输入法。
- 输入法提交或修正文字时，监听文本状态变化。
- 显示连接状态、发送状态、「新一段」、复制、停止同步等控件；一段结束后输入框自动清空，下一段追加到电脑。

**F-004 实时文本同步**
- 文本变化后以可配置的短延迟合并高频事件（默认 30–80 ms），通过 WebSocket 发送完整快照。
- 每个快照包含 `sessionId`、递增 `seq`、`text`、光标位置（可获得时）和时间戳。
- Windows 丢弃旧序号与旧会话消息。
- Windows 端能处理插入、删除、替换与整句修正，而不只是追加。
- 文本注入失败时暂停并显示错误，不无限重试造成重复文本。

**F-005 Windows 输入会话**
- 必须有明确的“开始输入 / 停止输入”控制。
- 默认仅在启动会话时捕获目标窗口；焦点变化后暂停并要求重新确认。
- 提供“测试输入”按钮，先在测试框中验证。
- MVP 优先支持普通 Win32 文本输入框、常见浏览器输入框与普通文本编辑器；特殊应用另行测试。
- 不承诺游戏、远程桌面、管理员权限窗口、终端 TUI 或所有自绘控件均兼容。

**F-006 双向纯文本剪切板**
- 支持开关、单向/双向模式。
- 防止来源事件回环和重复写入。
- 大文本有大小上限（建议 1 MiB，配置项）。
- 同步前可显示简短预览；敏感应用/密码管理器场景可关闭。

**F-007 Windows 托盘**
- 支持显示窗口、连接状态、开始/停止输入、剪切板同步开关、退出。
- 关闭主窗口默认最小化到托盘，退出操作需明确。
- 应用退出后停止网络监听和输入注入。

**F-008 通知栏快捷入口**
- Android 通知提供“打开语音输入”操作。
- 用户点击后打开 Activity，聚焦文本框并请求显示 IME。
- 不承诺从后台直接强行弹出键盘；系统可拒绝或延迟显示。
- 如果需要持续维持连接，采用明确通知与合适的前台服务策略；MVP 可先以前台连接为主。

**F-009 可诊断性**
- 显示最近连接错误、版本号、配对设备与网络状态。
- 日志不得默认记录完整输入文本、剪切板内容或认证令牌。
- 提供“复制诊断信息”，仅含脱敏状态信息。

### P1：MVP 后增强

- 多设备选择与自定义设备名。
- 全局快捷键与可配置的焦点保护策略。
- 输入会话中断恢复。
- 最近输入历史（默认关闭、可清除、加密存储）。
- 多语言 UI。
- 统计同步延迟与失败率（不上传云端）。
- Windows 端支持 Unicode 输入与剪切板粘贴两种注入后端，允许手动切换。

### P2：后续规划

- 图片剪切板同步。
- 文件传输（采用单独文件协议、大小限制、用户确认和完整性校验）。
- 多台 Windows/Android 设备。
- 可插拔离线语音方案（只有用户明确选择时才启用，不替代输入法方案）。
- Linux、macOS、iOS（不在当前版本承诺范围）。
- 远程网络中继（需另立威胁模型，不默认启用）。

## 5. 非目标

- 不自行实现语音识别、录音或语音模型。
- 不开发自定义 Android 输入法。
- 不使用无障碍服务模拟点击第三方输入法麦克风。
- 不要求 Root。
- 不通过云端中转文本。
- 不保证在 Windows 所有输入控件中注入成功。
- 不在后台无提示读取 Android 剪切板。
- 不在 MVP 实现图片、文件与 iOS。

## 6. 非功能需求

- 局域网文本同步目标：正常 Wi-Fi 下，从 Android 文本状态变化到 Windows 开始应用更新，P95 目标 ≤ 150 ms（不包含输入法自身识别延迟；硬件与目标应用可能影响结果）。
- 断线后自动重连；重连后通过会话 ID 和序号阻止旧消息覆盖新状态。
- 安全：配对认证、证书指纹校验、最小网络暴露、停止会话立即停止注入。
- 稳定性：异常退出、重复消息、网络抖动不得造成重复粘贴或无限循环。
- 隐私：默认不持久化语音文本；日志脱敏；用户可以随时断开和撤销设备授权。
- 可维护：协议有版本字段；核心逻辑有单元测试；Windows 输入注入封装为独立模块。

## 7. MVP 里程碑

- M0：仓库、构建链路、协议与安全基础。
- M1：Windows 与 Android 配对/连接，双端状态可见。
- M2：Android 输入框 → WebSocket → Windows 测试输入框的实时文本同步。
- M3：焦点保护、输入法兼容测试、通知栏快捷入口。
- M4：双向纯文本剪切板、托盘、日志、打包与验收。
- M5：发布候选版、文档与已知限制。

## 8. 产品成功指标

- 首次安装后，用户能在 5 分钟内完成配对（目标）。
- 主流 Android 输入法在测试机上可完成语音输入；不要求各输入法输出粒度一致。
- 测试环境中 100 次文本编辑/修正循环无重复文本、无跨窗口误注入。
- 断网恢复后不会将旧会话内容写入新焦点。
- 未配对客户端无法建立可用输入会话。
