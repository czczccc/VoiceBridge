# 安全与隐私设计

## 1. 安全目标

- 只有用户明确配对的设备可以连接并发送输入文本。
- 文本与剪切板内容仅在局域网设备间传输，不经过自建云服务。
- Windows 只在用户选定的私有网络上监听。
- 输入焦点变化后不继续注入。
- 日志不记录输入正文、剪切板正文或认证凭据。
- 用户可停止会话、断开设备、撤销配对并删除本地数据。

## 2. 威胁模型

需要考虑：
- 同一 Wi-Fi 下的其他设备尝试连接。
- 恶意或仿冒客户端向 Windows 注入文本。
- 配对码被旁观者截取或长期截图泄露。
- 局域网中间人读取或篡改文本。
- 旧消息在重连后重复执行。
- 恶意输入超大消息导致内存占用。
- 输入焦点变化造成文字进入密码框、终端或错误窗口。
- 日志或崩溃报告泄露个人文本。

不在 MVP 防御范围内：
- 已获得 Windows 管理员权限的本地恶意软件。
- 已被 Root/完全控制的 Android 系统。
- 用户主动授权的恶意第三方输入法。
- 用户自行关闭安全设置后产生的风险。

## 3. 网络与认证

- 使用 WSS，不使用无认证的明文 WebSocket 作为默认正式配置。
- Windows 首次运行生成本地证书与私钥。
- 配对二维码携带证书指纹，Android 必须进行证书 pinning，不能因为是自签名证书就跳过验证。
- 使用短时一次性配对 nonce；成功后失效。
- 配对码（数字比对）由两端根据证书指纹与两个 nonce 独立计算，不经过网络传输；用户核对不一致时必须拒绝。
- mDNS 广播只用于发现候选设备，广播内容（包含指纹）不可信，不得作为自动配对依据。
- 当前配对采用「本地确认」模式：手机发起请求后，由 Windows 本机用户点击「允许/拒绝」发放 token，不要求输入配对码。这能阻止同一局域网内的陌生设备静默配对，但无法阻止主动中间人转发后诱导用户点「允许」；高安全场景应启用配对码核对模式。
- 若启用配对码核对，配对码不一致时必须拒绝发放 token。
- 认证完成前只接受配对消息；其它消息一律拒绝。
- 认证凭据使用高熵随机值；Android 存入 Android Keystore 保护的存储，Windows 侧按操作系统能力保护。
- 设备撤销后立即拒绝其后续连接。
- 监听范围限制为用户选择的 LAN 地址；防火墙规则遵循最小权限。
- 不默认开启公网穿透、云中继或 UPnP 端口映射。
- 限制消息大小、频率、连接数和配对尝试次数。

## 4. 输入注入安全

- 输入会话由用户在手机上开始输入触发（用户明确动作在手机端）；电脑端不再要求额外点击。服务器在收到会话请求时捕获当前前台窗口，并拒绝 VoiceBridge 自身窗口作为目标。
- 电脑端提供「关闭自动同步」开关和「停止当前会话」按钮作为紧急停止手段。
- 会话启动（手机发起）时捕获当前前台窗口；每次注入前重新校验。
- 发现焦点变化、目标窗口消失、sessionId 失效或认证状态异常时，停止注入。
- 不自动把文本重定向到新焦点。
- 不尝试绕过 UAC 或向更高完整性级别窗口注入。
- 用户停止会话后，拒绝所有旧 session 消息。
- MVP 对密码框、凭据对话框和明显敏感目标应默认拒绝或要求明确二次确认；若无法可靠识别控件类型，UI 必须清楚提示用户自行确认目标窗口。

## 5. 剪切板隐私

- 默认仅启用纯文本同步。
- 用户可分别关闭 Android→Windows 和 Windows→Android。
- 不在后台无提示读取 Android 剪切板。
- 对密码管理器等敏感场景提供暂停/排除策略；不能可靠识别所有密码框，因此不要把自动检测作为唯一保护。
- 不记录剪切板内容。
- 剪切板同步不等于输入会话；停止输入会话不应意外继续注入文本。

## 6. 数据生命周期

- 默认只在内存中保留当前输入会话文本。
- 不建立云端账号，不上传遥测。
- 默认不保存输入历史。
- 调试日志只记录事件类型、序号、耗时、错误码和脱敏设备 ID。
- 用户断开设备后可撤销凭据；用户清除数据时删除本地配对信息。
- 崩溃报告不得包含文本正文、配对二维码、证书私钥或访问令牌。

## Android 测试更新渠道

- 按用户追加，允许经 HTTPS 访问公开 GitHub Releases 获取版本清单和 APK，不传输输入文本、剪切板或配对凭据；此请求与局域网业务协议分离。
- 清单限定当前仓库 android-testing 渠道和版本化 APK 文件名；拒绝无效版本、超大清单/下载和错误 SHA-256。
- 安装前验证包名、版本与当前安装的签名证书一致；最终安装仍由 Android 系统校验与用户确认。
- main 构建使用 GitHub Secrets 固定签名，PR 不接触密钥、不发布；发布权限仅开放给发布任务。
- 密钥与密码不进入版本控制、不在日志打印。签名初始化在用户目录创建受限访问的备份，需用户长期妥善保存。
- 当前更新依赖公开 GitHub 可达性和仓库/签名密钥安全；首次 APK 来自用户信任的 Releases。清单无独立签名，APK 签名是应用身份校验依据。

## Windows 测试更新渠道

- 与 Android 同理，经 HTTPS 访问公开 GitHub Releases 获取 `latest.json` 与 NSIS 安装包；不传输输入文本、剪切板或配对凭据。
- 更新包必须通过 Tauri updater 的 minisign 签名校验，公钥内置在应用中；清单无独立签名时仅凭安装包签名和版本号判断。
- 安装包为当前用户安装，`passive` 模式自动安装，不请求管理员权限、不引导用户手动下载安装包。
- 私钥只存在于开发者本机与 GitHub Secrets，不进入版本控制、不写入日志；私钥丢失将导致已安装用户无法接收更新。
- PR 构建不启用更新产物，也不接触签名密钥。
- 安装包未做 Windows 代码签名，SmartScreen 可能提示未知发布者；用户需自行判断来源。

## 7. 安全验收

- 未配对设备无法完成认证。
- 修改证书指纹或使用错误证书时 Android 拒绝连接。
- 过期配对码不能重复使用。
- 旧 session、旧序号与重复消息不会重复注入。
- 超过消息大小上限的消息被拒绝。
- 焦点变化后输入立即暂停。
- 日志中搜索不到测试用敏感字符串和认证令牌。
